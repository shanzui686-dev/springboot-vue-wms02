### 2. 分页查询接口优化 (`/goods/listPage`)

#### 接收参数
- `name`: 商品名（模糊查询）
- `categoryId`: 分类ID（精确匹配）
- `warehouseId`: 仓库ID（精确匹配）
- `isWarning`: 布尔值，是否只看告急商品

#### 核心逻辑
使用 MyBatis XML 连表查询实现：

1. **连表查询**：
   - `LEFT JOIN supplier` - 获取供应商名称
   - `LEFT JOIN goodstype` - 获取分类名称
   - `LEFT JOIN storage` - 获取仓库名称

2. **动态条件**：
   ```xml
   <!-- 商品名模糊查询 -->
   <if test="name != null and name != ''">
       AND g.name LIKE CONCAT('%', #{name}, '%')
   </if>
   
   <!-- 分类ID精确查询 -->
   <if test="goodsType != null">
       AND g.goodsType = #{goodsType}
   </if>
   
   <!-- 仓库ID精确查询 -->
   <if test="storage != null">
       AND g.storage = #{storage}
   </if>
   
   <!-- 告急商品筛选：当前库存 <= 安全库存 -->
   <if test="showUrgentOnly != null and showUrgentOnly == true">
       AND g.count <= g.min_count
   </if>
   ```

3. **返回数据**：
   - 返回 `GoodsVO` 对象，包含所有关联表的名称字段
   - 前端无需二次查询即可显示分类、仓库、供应商名称

### 4. 关键代码示例

#### Controller 层
```java
@PostMapping("/listPage")
public Result listPage(@RequestBody QueryPageParam query){
    HashMap param = query.getParam();
    String name = (String) param.get("name");
    Object categoryIdObj = param.get("categoryId");
    Object warehouseIdObj = param.get("warehouseId");
    Object isWarningObj = param.get("isWarning");
    
    String categoryId = categoryIdObj != null ? categoryIdObj.toString() : null;
    String warehouseId = warehouseIdObj != null ? warehouseIdObj.toString() : null;
    Boolean isWarning = isWarningObj != null ? Boolean.parseBoolean(isWarningObj.toString()) : false;
    
    Page<GoodsVO> page = new Page<>();
    page.setCurrent(query.getPagenum());
    page.setSize(query.getPagesize());
    
    Integer categoryIdInt = StringUtils.isNotBlank(categoryId) && !"null".equals(categoryId) 
        ? Integer.parseInt(categoryId) : null;
    Integer warehouseIdInt = StringUtils.isNotBlank(warehouseId) && !"null".equals(warehouseId) 
        ? Integer.parseInt(warehouseId) : null;
    
    IPage<GoodsVO> result = goodsMapper.selectGoodsWithSupplier(
        page, name, categoryIdInt, warehouseIdInt, isWarning);
    return Result.suc(result.getRecords(), result.getTotal());
}
```

#### Mapper XML 层
```xml
<select id="selectGoodsWithSupplier" resultType="com.wms.entity.GoodsVO">
    SELECT
        g.id,
        g.name,
        g.storage,
        g.goodsType,
        g.count,
        g.min_count AS minCount,
        g.barcode,
        g.specs,
        g.unit,
        g.retail_price AS retailPrice,
        g.purchase_price AS purchasePrice,
        g.supplier_id AS supplierId,
        s.name AS supplierName,
        gt.name AS categoryName,
        st.name AS warehouseName,
        g.remark
    FROM goods g
    LEFT JOIN supplier s ON g.supplier_id = s.id
    LEFT JOIN goodstype gt ON g.goodsType = gt.id
    LEFT JOIN storage st ON g.storage = st.id
    <where>
        <if test="name != null and name != ''">
            AND g.name LIKE CONCAT('%', #{name}, '%')
        </if>
        <if test="goodsType != null">
            AND g.goodsType = #{goodsType}
        </if>
        <if test="storage != null">
            AND g.storage = #{storage}
        </if>
        <if test="showUrgentOnly != null and showUrgentOnly == true">
            AND g.count <= g.min_count
        </if>
    </where>
    ORDER BY g.id DESC
</select>
```

### 7. 注意事项

1. **参数兼容性**：Controller 已将参数名从 `goodstype`/`storage`/`showUrgentOnly` 改为 `categoryId`/`warehouseId`/`isWarning`，前端需同步更新
2. **告急条件**：使用 `count <= min_count`（小于等于），而非原来的 `count < min_count`（小于）
3. **连表性能**：已使用 LEFT JOIN，确保即使关联数据不存在也能查到主表数据
4. **BigDecimal 精度**：`purchasePrice` 使用 `DECIMAL(10,2)`，支持最大 8 位整数 + 2 位小数
